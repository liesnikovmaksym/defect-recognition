# Розпізнавання дефектів фігур (Brain.js)

Лабораторна, варіант 8: нейромережа розпізнає круг/квадрат **без дефекту** та **зі зайвими «висячими» виступами**.
Вхід мережі — **кумулятивна гістограма яскравості** зображення.

Стек: React 19, Redux Toolkit, SCSS + CSS Modules, Vite, Brain.js 1.6.1 (у Web Worker), Recharts (графіки), ExcelJS (експорт в Excel, підвантажується за потреби), шрифти IBM Plex Sans і Mono (``@fontsource``). Архітектура — FSD.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
```

## Як це працює

1. **Датасет.** Фігура описується спекою (тип, центр, радіус, виступи) і малюється на canvas у роздільності групи.
   Групи (Assets) за якістю: Іконки 32×32, Стандартні 128×128, Якісні 1024×1024. Можна вчити всі групи (Assets) або окремі.
   Кожне зображення кодується у файл PNG / JPG / BMP (або змішано), потім декодується: це повний шлях «файл -> ознаки».
   За замовчуванням 300 зображень на групу (900 разом).
   Фігури обираються в датасеті (за замовчуванням лише круг): круг, еліпс, квадрат, прямокутник, трикутник, шестикутник. Варіативність: «Базова»
   (фіксований розмір, прямі виступи) або «Розширена» (розмір, поворот, виступи двох видів: прямий і «крапля»).
   Гістограма не відрізняє фігури одну від одної, тому найкращу точність дає окрема модель на одну фігуру.
2. **Ознаки** (перший спосіб зі статті Мельника, розділ про ANN для дефектів): зразок порівнюється з **еталоном**, тобто фігурою без
   дефектів по центру (радіус 30% полотна). Різницеве зображення ділиться на надлишок (зразок світліший) і нестачу (темніший),
   для кожного рахується кумулятивна гістограма (`shared/lib/ml/diff.js`, 32 корзини; нульова корзина — допуск 256/32 = 8 рівнів),
   разом 2 × 31 = 62 входи. Для зразка, що збігається з еталоном, усі значення нульові. Зразки в датасеті вирівняні з еталоном,
   як пари «еталон + зразок» у статті; відрізняються лише виступи. Світлий фон автоматично інвертується, ознаки мін-макс нормуються.
3. **Мережа**: `NeuralNetwork` Brain.js, однощарова мережа без прихованих шарів, як у статті. Налаштовуються кількість епох і швидкість навчання.
4. **Розпаралелення.**
   - Підготовка зображень: пул Web Workers (`shared/api/ml/pool.js`, `prep.worker.js`), порції по 6 зображень із динамічної черги.
     Режим і кількість воркерів обираються в інтерфейсі; є режим «Головний потік» для порівняння.
   - Навчання та розпізнавання: окремий воркер (`train.worker.js`), інтерфейс не блокується.
5. **Інтерфейс**: одна центральна картка з перемикачем.
   - Вкладка «Розпізнавання»: перемикач «Файл / Малювання». Файл: file uploader на весь блок. Малювання: полотно з пензлем, гумкою, скасуванням і готовими фігурами (круг, квадрат), щоб дорисувати виступ; після завантаження замість нього показується зображення
     (з іконкою Info, збереженням у PNG/JPG/BMP та кнопкою «Замінити зображення»); нижче кнопка «Розпізнати дефекти»,
     окремий progress bar і результат (вердикт, гістограма, збереження результату в Excel (.xlsx) та JSON).
   - Вкладка «Навчання моделі»: замість uploader з'являється форма навчання (набір даних, розпаралелення, епохи,
     швидкість навчання), два progress bar (зображення та епохи), таймер, графік помилки та метрики.
   - Моделі: кожне навчання зберігається у `localStorage` (ваги, нормування, метрики, параметри) і переживає
     перезавантаження сторінки. Список моделей (обрати, перейменувати, видалити) — під навчанням, а вибір моделі для
     розпізнавання — на вкладці «Розпізнавання» під зображенням.
   - Navbar (sticky) зверху з кнопками «Історія розпізнавання» і «Логи»: кожна відкриває випливаючу панель справа
     (ширину можна змінювати перетягуванням краю). Історія зберігає файл, вердикт, модель і час кожного розпізнавання;
     лог можна зберегти у .txt. (в інтерфейсі + збереження у .txt).

## Структура (FSD)

```
src/
  app/         store (+ слухач логування), провайдери, глобальні стилі
  pages/       home
  widgets/     navbar, workspace (зображення / навчання), result-panel (результат), history-panel, log-panel
  features/    train-model, upload-image, draw-shape, generate-sample, recognize-image, save-image, export-results
  entities/    image, model, recognition, log (slice + ui)
  shared/      ui, lib (ml, image, format), api/ml (воркери), config, styles
```

Імпорти йдуть лише вниз по шарах (`pages → widgets → features → entities → shared`), назовні — через `index.js` слайсу.
